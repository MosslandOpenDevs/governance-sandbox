# Web Demo Result Card Acceptance

Use this note when the first governance-sandbox web demo needs a compact acceptance bar before adding more screens or branches.

## Acceptance bar

1. One scenario fixture or form submission produces a stable result card.
2. The card keeps proposal, audience, and recommendation text readable in one view.
3. One report artifact or download path is reachable from that same proof flow.
4. The replay note names the fixture, validation command, and browser checkpoint used.

## Why it exists

This keeps the first web-demo slice aligned with scenario-file truth, UI/UX clarity, and Playwright-style step verification before the demo grows wider.
